## B. Cheaper Clinic egress (NAT instance)

Before: managed NAT gateway `nat-02829358e83dd5986` plus its Elastic IP, about 38 + 3.65 USD per month plus 0.052 USD per GB. After: one `t4g.nano` NAT instance `i-09d3f1ce96920f95d` (plain Amazon Linux 2023, nftables masquerade, source/destination check off, IMDSv2 only, encrypted 8 GB gp3, SSM access, Elastic IP `3.70.36.128`), two CloudWatch alarms (system check fails: EC2 recover; instance check fails 3 minutes: reboot). About 8.6 USD per month all in (instance 3.9, Elastic IP 3.65, volume 0.8, alarms 0.2), saving about 33 USD per month. Code: `modules/clinic_link` (variables `egress_gateway_enabled`, `egress_instance_enabled`, `egress_route_via`), values in `envs/test/terraform.tfvars`.

Steps and checks:
1. `tofu plan -target=module.clinic_link`: 8 to add, then apply (nothing of the Clinic, RDS or App Runner in any plan; an unrelated tag drift on the host data volume was left alone by targeting).
2. First boot failed: `dnf` was OOM-killed on 0.5 GB (the repository metadata is large). Fixed by a 1 GB swap file in the user data (the script in `main.tf` is the corrected one and was run once over SSM on the live instance); the reboot test proved forwarding, the masquerade rule and the swap survive a reboot.
3. Proof before the switch: a temporary probe instance in the Clinic's public subnet (no public address) reported the managed gateway's address `52.57.103.77` and 200 from Passport, the platform and the legacy CloudFront host. A first probe with the VPC default security group looked broken only because that group has no outbound rule (CDK default).
4. Cutover: `egress_route_via = instance` (two in-place route changes, about 2 seconds). The same probe then reported `3.70.36.128` and the same three 200s. `npx playwright test -c e2e/kx-test 07-clinic-wiring` 18 passed (browser Clinic to Passport chain with the server-side token exchange from App Runner, signed provider and slot sync).
5. Removal: `egress_gateway_enabled = false` destroyed the gateway and its Elastic IP (the address release needed one retry while AWS detached the gateway's interface). Probe instance and its temporary security group deleted.
Trade-offs: a single instance (no managed multi-AZ; recovery by alarm takes a few minutes during which the Clinic API cannot call Passport or the platform, sign-in with passwords and the staff app keep working), lower sustained bandwidth (baseline roughly 32 Mbps, bursts to 5 Gbps, far above the Clinic's calls), the outbound address changed once (nothing allow-lists it), the user data is not re-applied by tofu (`ignore_changes`).
Rollback to the managed gateway (about 2 minutes): in `envs/test/terraform.tfvars` set `clinic_egress_gateway_enabled = true` and `clinic_egress_route_via = "gateway"`, `tofu apply -target=module.clinic_link` (creates gateway and Elastic IP, then points the two routes at it), verify, then `clinic_egress_instance_enabled = false` and apply again.
