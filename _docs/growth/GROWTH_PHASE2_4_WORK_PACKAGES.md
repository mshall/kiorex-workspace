## 1. Cross-cutting rules for every package in this file

1. **Additive only.** No existing column, enum value, event field or endpoint changes meaning. New columns nullable or defaulted. Flags default per ADR-023: engine pieces `ON` in dev and staging, anything that sends marketing, issues or redeems money, runs the WhatsApp model, collects visitor analytics, or touches corporate or loyalty is **launch-locked** (needs a human-recorded gate in the Super Admin, never recorded by code).
2. **No PHI in growth.** Specialty, doctor, visit reason, diagnosis, prescription, lab or pharmacy contents never join a growth identity, an ad payload, a segment or a model prompt. Existing `growth-no-phi.unit.spec.ts` is extended per package; `no-health-targeting.unit.spec.ts` (ARCH 14) lands in P2-F and covers every new module.
3. **Money paths are append-only and idempotent** (ledger entries, decisions, spend approvals). Two-person rule on every configuration that moves money or messaging (existing `GrowthConfigVersion` maker-checker).
4. **Mock-first, config-only real.** Every adapter has `mode: mock | real`; real mode needs `secretRef` names (validated `^[a-z0-9/_-]+$`) and is never exercised in CI.
5. **AR and EN, RTL, tokens.** Every UI string in both languages in the namespaced i18n file of the package, Arabic default in Egypt, Arabic-Indic digits via the existing formatter, brand tokens (`_brand`), `prefers-reduced-motion`, 44 px touch targets, 320 px to 2560 px layout check in Playwright.
6. **Tests named like existing ones.** KP: `*.unit.spec.ts`, `test/*.int.spec.ts`; CM: `*.node.test.ts`, `*.integration.test.ts`; KC, KA, KL: vitest or jest as today. E2E suites continue the numbering: `29` to `39` are reserved here (section 12).
7. **Each package ends with:** unit and integration tests green, lint and typecheck green, OpenAPI regenerated (`openapi-export.ts` in KP, `openapi:export` in CM) and `Docs/API.md` regenerated, `Docs/GROWTH.md` section, flag documented, `Docs/NEEDS_HUMAN.md` row updated if a gate or placeholder is introduced, requirement id in the Conventional Commit, no secret or build output in git.
8. **Retention and erasure.** Every new table that holds a `sub` or a hash derived from a person is registered with `growth_erase_subject` (extend the SQL function in that wave's migration, never edit an old one), and with `growth_purge_expired` (new retention arguments added through a new function version `growth_purge_expired_v2`).
9. **Observability.** Every job writes a heartbeat row (`GrowthJobRun`, created in X1) and increments the existing job metrics; every package adds its SLIs to `Docs/GROWTH.md` section "SLOs" (ARCH 20 pattern).

## 4. Strategies applying to all waves

### 4.1 Parallelisation rules

At most four agents per wave. Each agent owns a repo-and-folder set listed in the wave tables; if two packages must touch one file the single owner of section 2 does it. An agent that finishes early takes only **tests, docs or Playwright for its own package**, never another agent's folder. Agents commit in small Conventional Commits with the package id (`feat(growth): GRW-P2-A campaign state machine`), `Co-Authored-By` trailer, no push.

### 4.2 Contract versioning plan

See 0.2. The order inside a wave is fixed: contracts first (X0 or the wave's contract task), tarball vendored, **then** schema, **then** services, **then** UI. A package never depends on an unreleased contract; if it needs a field that is missing it requests a patch release (1.12.1) from the contract owner.

### 4.3 Migration ordering plan (avoid out-of-order names)

Rule: a migration directory name (`YYYYMMDDHHMMSS_name`) must sort strictly after every migration already on `main` of that repo at merge time, and each wave reserves a **numeric block** so concurrent agents cannot interleave. Slots below are reserved; they intentionally use calendar-looking prefixes after the latest names observed (KP `20261130090000_growth_link_registry`; CM `20261201090000_shared_rate_limit_and_nonce`; PH and LB latest `20261126120000_*` pattern, CONFIRM AT START with `ls prisma/migrations | tail`). If a hotfix migration lands first with a later name, the schema owner renames its own (unmerged) directory to the next free second inside the block before merging; never edit a merged migration; never reuse a name.
