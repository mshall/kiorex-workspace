# Test flow: patient referral engine and rewards ledger (GRW-P2-B1, GRW-P2-B2)

API only (screens are GRW-P2-B3). All providers are mocks. Everything is OFF until a human records gate evidence; in a test stack use the fixture helper `unlockFlag` (DEV-prefixed gate id, never a real gate).

1. **Switch on (dev stack)**: record test gate evidence for `growth.patient_referral` and `growth.rewards` (and, for credit, `growth.patient_credit`, `growth.refund_as_credit`, `growth.family_credit`, `growth.support_goodwill`). Activate `REWARD_RULES` and `REFERRAL_RULES` through the Growth config console with two super admins; the shipped defaults are all 0 and issue nothing. For credit mode set `mode: CREDIT`, `credit.refundAsCredit.enabled: true`, `credit.family.enabled: true`.
2. **Referral**: patient A `GET /api/v1/growth/v1/referral/me` returns the code; patient B (new account, verified phone) `POST .../referral/claim {code}` returns `SIGNED_UP`; claiming again, or another code, returns the same. A self claim, an unknown code and a suspended code each return `409 REFERRAL_REJECTED` with the same shape.
3. **Qualify**: B books and the Clinic sends `COMPLETED` (webhook); the relationship becomes `BOOKED` with `holdUntil` 7 days ahead. After the hold (or `ReferralExpiryJob.run(now + 8 days)` in a test) it becomes `QUALIFIED`; one voucher (or credit lot) is issued to each side; exactly one `ReferralQualified` outbox event exists.
4. **Redeem**: B `GET .../referral/rewards`, `POST /growth/v1/rewards/:lotId/reveal` (the code is shown once), then `POST /bookings/:id/deposit-checkout {lotId}` (or `{couponCode}`): `amountMinor` is the card amount, `rewardMinor` the credit, `lines` the ordered checkout lines. Pay the fake checkout; the Clinic `deposit-paid` call carries the GROSS amount and `tender`.
5. **Refund destination**: `POST /pay/v1/refunds/preview {bookingRef}` lists "original payment method" first and as the default. `POST /bookings/:id/cancel {refundDestination:"CREDIT"}` keeps the card refund as one `REFUND_CREDIT` lot (only with all three switches on, else 422); without the field the refund goes to the card. After `RewardExpiryJob.runOnce(now + 13 months)` the unspent rest returns to the original method.
6. **Ops**: `/admin/growth/referrals` (aggregate, k >= 10), reviewer view and decisions; `/admin/growth/rewards/lots`, `.../finance?month=YYYY-MM` (finance role), `/admin/growth/credit/goodwill` (support role; a second approver above the threshold at `/admin/growth/rewards/approvals/:id/decide`), `POST /admin/growth/credit/reconcile/run` (RC-1 to RC-7).
7. **Automated evidence**: `npm run test:unit -w apps/api` (reward-math with the shared vectors, referral code, qualification, fraud rules, goodwill limits, repository guards S1 to S10) and `npx jest --selectProjects integration --runInBand --testPathPatterns 'growth-(rewards|referral|credit)'` in `kiorex-platform/apps/api`.
