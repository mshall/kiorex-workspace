# Campaign management (GRW-P2-A): how to run and what each test proves

Stack: Kiorex API :4000 (restarted with `e2e/scripts/up.sh --build --restart --seed --only=kiorex`, which also applies the Phase 2 migrations), Passport :4400, ops console :5181. Providers are mocked; no ad platform exists anywhere in the flow.

| Layer | Command | What it proves |
|---|---|---|
| Pure units | `cd kiorex-platform/apps/api && npm run test:unit -- campaigns` | the state table (all 49 state pairs, 13 legal), guardrail vectors (approval rule, ceiling pro rata, utilisation rounding, thresholds, spend line rules, asset references), the non-clinical audience allowlist, the UTM builder, Cairo day boundaries including both DST nights |
| Integration | `npx jest --selectProjects integration --runInBand --testPathPatterns growth-campaigns` | lifecycle over HTTP with a second admin, self-approval refused (service and database), approval invalidation by edits, ceiling, alerts firing once, auto pause at 100 percent, budget increase approval, daily cap rollover at Cairo midnight, scheduler idempotency (two concurrent runs), flag OFF contract, role matrix, spend de-duplication, creative references, UTM touch tag (ACTIVE only), report equals the tables, `<10` masking, "not connected", rollup campaign dimension, no outbound HTTP in the module |
| Ops unit | `cd apps/ops && npx vitest run src/__tests__/growth-campaigns.test.tsx` | list, wizard (five steps, validation, non-clinical audience in the posted body), detail actions with reasons, report masking, Arabic, approvals page (requester cannot decide, hash sent) |
| Playwright | `cd apps/ops && npx playwright test e2e/growth-campaigns.spec.ts --project=chromium` | the real two-admin approval through the console, the read-only role, and a 12-cell matrix (AR and EN x light and dark x 320, 768, 1440 px) with RTL, no horizontal overflow and axe serious and critical clean on the list, wizard, detail, approvals and promotions pages. Screenshots land here in `_docs/test-flow/growth-p2/` |
| End to end | `cd e2e && npx vitest run test/29-growth-campaigns.e2e.ts` | the same journey on the real API with real Passport sessions: plan, approval by the second super admin, scheduler start, public resolve, approved spend reconciled to the piastre, alerts, budget pause and increase, daily cap guardrail, a campaign touch followed by a real booking (MARKETPLACE decision with the campaign as winning touch, rollup row with the campaign id, report masks one person), flag OFF contract, completion, archive and audit |

Cleanup: suite 29 removes its campaigns, spend lines, metric rows, touches and outbox rows at the end (`purgeCampaigns`, triggers off for one transaction, dev database only). The Playwright spec completes and archives its campaign (history is append-only by design).
