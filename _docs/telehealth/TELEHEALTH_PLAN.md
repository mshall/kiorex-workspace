# Kiorly Clinic Telehealth: findings and implementation plan (read-only exploration, 23 Nov 2026)

Repo: `kiorex-v2/clinics-management` (branch `kiorex`). Paths below are relative to it unless prefixed `../`. Nothing was edited or committed.

## 1. Findings (what exists today)

1. **Layout.** npm workspaces: `apps/api` (NestJS 12, Prisma 7, node:test), `apps/web` (React 19, Vite, react-router 7, i18next, Playwright), `packages/field-visit`, `infra/tofu`. One folder per module in `apps/api/src/<module>`; each must be mapped to a bounded context in `src/platform/module-contexts.ts` (module-boundaries test) and imported in `src/app.module.ts`. Closest analogue to copy: `src/home-visits/` (ADR-030: HOME service location, own module, scheduler, internal job controller, event builders validated against contract schemas).
2. **Auth/guards.** `JwtAuthGuard`, `SubscriptionAccessGuard` + `@RequiresSubscriptionAccess(SubscriptionAccessAction.SCHEDULING_WRITE)`, `@RequiresScope("encounter.sign")` + `ScopeGuard` (`src/scope-of-practice`), `@RequiresFeature(key)` + `FeatureGuard`, `@RequiresEntitlement`. Role sets in `src/user-nav-tabs/nav-tab-module-roles.ts` (`APPOINTMENTS_*`, `ENCOUNTERS_*` = roles holding the nav tab, `src/user-nav-tabs/nav-tab-keys.ts`) enforced by `NavTabAccessService.assertViewTab/assertMutateTab`. Roles (`UserRole`): GROUP_ADMIN, GROUP_SUPERVISOR, BRANCH_MANAGER, PHYSICIAN, NURSE, RECEPTIONIST, CALL_CENTER, CLINIC_ADMIN, CLINIC_ASSISTANT, etc.; multi-role helpers in `src/common/effective-roles.ts`. PHYSICIAN is restricted to own appointments/encounters (`assertAppointmentAccess` in `appointments.service.ts`, `assertPhysicianEncounterAccess` in `encounters.service.ts`); clinic-scoped roles are limited by `ClinicAdminScope`.
3. **Every controller must be listed** in `CONTROLLER_ENTITLEMENT_POLICIES` (`src/entitlements/plans-matrix.ts`, test `pl04-controller-coverage`); public/token controllers use `{kind:"open"}`, HMAC ones `{kind:"webhook"}`. Entitlement keys live in `MODULE_ENTITLEMENT_KEYS`, `ENTITLEMENT_MIN_PLAN`, per-plan matrix in the same file, plus plan seeds and doc test `pl04-matrix-doc`. Plans: LITE, PRO, CLINIC, ENTERPRISE, NURSE_*.
4. **Prisma conventions.** Single `apps/api/prisma/schema.prisma` (5172 lines), cuid ids, `tenantId` + `tenant` relation `onDelete: Cascade` on every row, `@@index([tenantId, ...])`, timestamps `createdAt/updatedAt`, Decimal(14,2) money, enums at the top, SQL migrations in `apps/api/prisma/migrations/<yyyymmddhhmmss>_<name>/` (184 so far, latest `20261123150000_kiorex_import_receiver`; `migration-order.node.test.ts` guards ordering). Seeds: `prisma/seed.ts`, `prisma/demo/seed-demo.ts`, `prisma/kiorex-dev.seed.ts`, `prisma/demo/seed-rev23.ts`.
5. **Appointment model** (`schema.prisma` ~L2452): status enum `SCHEDULED, CONFIRMED, CHECKED_IN, COMPLETED, CANCELLED, NO_SHOW`; there is NO `visitType` column. Visit semantics come from `AppointmentType` (`serviceLocation: IN_CLINIC|HOME`, duration, buffers, fee, `marketplaceBookable`, deposit) copied onto `Appointment.serviceLocation`. `Encounter.visitType` is a free String and the web already lists `"Telehealth"` (`apps/web/src/lib/visit-types.ts`, locale key `encounters.visitTypes.telehealth`). Other relevant fields: `bookingSource` (FRONT_DESK, PHONE, WALK_IN, CLINIC_LINK, KIOREX_MARKETPLACE, KIOREX_WHATSAPP, INTEGRATION, IMPORT), `externalReference` + `platformIntegrationClientId` (unique), `isNewPatientAtBooking`, `rescheduleCount`, `cancelledBy/cancellationReason/depositRefundable`, `checkedInAt`, queue fields.
6. **Status machine / check-in** is in `src/appointments/appointments.service.ts`: `updateStatus` (L830) and `update` (L945) both run in one transaction: `frontDeskFlow.buildCheckInStatusPatch` (queue ticket, WAITING), `ensureDraftEncounterIfCheckedIn`, `commissionCharges.onCheckIn(tx, tenantId, id, checkedInAt)`, `depositSettlement.settleAppointmentDepositsTx`, `syncHomeVisitWithAppointmentStatus`, `appointmentOutbox.emitStatusChange`. Un-check-in reverts via `onRevert` and deletes draft encounters.
7. **In-person check-in -> encounter path EXISTS.** `src/front-desk/ensure-draft-encounter-on-check-in.ts` (`ensureDraftEncounterOnCheckIn`, `ensureDraftEncounterIfCheckedIn`): creates a DRAFT `Encounter` linked via `appointmentId`, patient/clinician/clinic/fee from the appointment, hard-coded `visitType: "Outpatient"`, idempotent only against DRAFT/AMENDED rows (a FINALIZED one would not block a duplicate; `Encounter.appointmentId` is not unique). Also called lazily from `finishAppointmentDto`. `EncountersService.create` also accepts `appointmentId` and infers clinician from it.
8. **Reschedule logic.** Staff: `AppointmentsService.update` (PATCH `/appointments/:id`) emits `RESCHEDULED` outbox when `startsAt` changes, invalidates slots. Patient via Kiorex: `MarketplaceBookingService.rescheduleByPatient` (policy check `evaluatePatientReschedule` in `src/marketplace/kiorex-booking-policy.ts`, Serializable tx + advisory lock, overlap check, `rescheduleCount++`, `emitRescheduled`, audit `marketplace.booking.rescheduled_by_patient`). Public patient link reschedule exists: `src/messaging/appointment-reschedule-token.service.ts` (hashed token table `AppointmentRescheduleToken`, web route `/r/:token`, base URL `APP_WEB_URL`).
9. **Marketplace API** (`src/marketplace/marketplace.controller.ts`, base `/marketplace/v1`, HMAC `MarketplaceAuthGuard` with headers `X-Kiorly-Client-Key/Timestamp/Nonce/Signature`): `GET clinics`, `providers`, `physicians`, `clinics/:clinicId/slots`, `POST holds` (5 min, `SlotHoldService`), `DELETE holds/:id`, `POST bookings` (Idempotency-Key = `externalReference`; `MarketplaceBookingService.createBooking`; body has `typeId`, `holdId`, `patient`, `notes`, `visitAddress` for HOME), `GET bookings/:externalRef`, `POST bookings/:externalRef/cancel`, `/reschedule`, `/deposit-paid`, waitlist, reviews, payouts, record-share consents, nurse endpoints. Slots/holds/bookings filter by `appointmentType.marketplaceBookable`; HOME gets special-cased by `serviceLocation`. A telehealth type fits the same pattern (a new `serviceLocation=VIDEO` or equivalent on the type).
10. **Outbound events** (outbox `OutboxEvent`, `src/messaging/outbox-event-types.ts`, dispatcher `outbox-dispatcher.service.ts` + scheduler, HMAC delivery `outbox-delivery.service.ts` to Kiorex `/api/v1/webhooks/kiorly`): `APPOINTMENT_CONFIRMED`, `RESCHEDULED`, `CANCELLED_BY_CLINIC`, `CANCELLED_BY_PATIENT`, `CHECKED_IN`, `CHECK_IN_REVERTED`, `COMPLETED`, `NO_SHOW`, `SLOTS_CHANGED`, `PROVIDER_PROFILE_UPDATED`, `LISTING_STATUS_CHANGED`, `COMMISSION_CHARGE_CREATED/REVERSED`, `REVIEW_INVITATION_ELIGIBLE`, `VISIT_SUMMARY_SHARED`, `PRESCRIPTION_SHARED`, `WAITLIST_OFFER`, v2.3 `HOME_VISIT_*`. Envelope `{eventId,type,aggregateType,aggregateId,occurredAt,target,data}`; targets `KIOREX`, `INTERNAL`, `TENANT_WEBHOOK:<id>`; 8 attempts then DEAD. Kiorex ignores unknown types (`../kiorex-platform/apps/api/src/webhooks/webhooks.service.ts` default -> IGNORED), so `telehealth.session.*` is safe to emit but Kiorex will not act on it until it is taught.
11. **Notifications.** Channels SMS/WHATSAPP/EMAIL (`MessageChannel`), `MessagingService.queueMessage` -> `OutboundMessage` rows -> `outbound-message.worker.ts` (SMS port `messaging/providers/sms.port.ts`), email (`email.service.ts`, `email-templates.ts`), WhatsApp (templated, consent required), push (`src/push`), dev inbox (`src/dev-inbox`). Provider mode `mock|real` via `src/common/provider-mode.ts` (`KIORLY_PROVIDER_MODE_<KIND>`). Consent: `MessagingConsent` (purpose `MESSAGING_CONSENT_TRANSACTIONAL`), enforced by `consent.assertCanSend`. Reminder scheduler: `src/messaging/appointment-reminder.scheduler.ts` is an in-process 60 s `setInterval` with ONE WhatsApp reminder N hours before (tenant `appointmentReminderHoursBefore`, default 24), deduped by an existing `OutboundMessage` for `templateKey` + `appointmentId`. Pattern for timers: `home-visits/home-visit-safety.scheduler.ts` (skipped when `NODE_ENV=test` or `KIORLY_DISABLE_SCHEDULERS=1`) and EventBridge jobs hitting `/api/v1/internal/jobs/...` guarded by `InternalJobKeyGuard` (`X-Internal-Job-Key`; Tofu `scheduled_jobs` in `infra/tofu/live/*/terraform.tfvars`).
12. **Feature flags.** Registry `src/feature-flags/feature-flag-keys.ts` (`CLINIC_FLAG_DEFINITIONS`), evaluated locally from the Kiorex snapshot (`kiorex-flag-snapshot.service.ts`, poll 30 s + `flag.changed` webhook); `@RequiresFeature` / `requireFeature(flags, tenantId, key)` -> 403 `FEATURE_DISABLED`; enforcement map `flag-enforcement.ts` (test `ff04`), labels `apps/web/src/lib/feature-flag-labels.ts`, docs `Docs/FEATURE_FLAGS.md`. **Drift test `ff01-registry.node.test.ts` requires the registry to equal `../kiorex-contracts/flags/catalogue.json`** (so a new flag needs a contracts change). All current Clinic keys are `clinic.*`; `telehealth.video` is not in the catalogue. Launch-locked flags need gate evidence; "ON by default" means class Module/Commercial, `launchLocked:false`.

## 2. Contracts and existing telemedicine

- **Marketplace contract schemas live in `../kiorex-contracts`** (`openapi/kiorly-marketplace.v1.openapi.json`, `events/*.schema.json`, `flags/catalogue.json`, v1.8.0, `src/generated/`), not in Clinic. Clinic keeps a snapshot `apps/api/openapi/marketplace.openapi.json` + `kiorex-consumer-contract.json` guarded by qa04. Contract rule: additive = minor bump. The marketplace OpenAPI `ServiceLocation` enum is `IN_CLINIC | HOME` and says "VIDEO is reserved and not part of this contract". So flow A needs a contracts PR (1.9.0): add `VIDEO` (or `TELEHEALTH`) to `ServiceLocation`, optional `telehealth` block in booking responses, new events `telehealth.session.created/started/ended/missed` schemas, and the flag entry.
- **Kiorex already has `kiorex.telemedicine`** (launch-locked, "Video option hidden", gate: clinical governance sign-off; `../kiorex-contracts/flags/catalogue.json`) and a module `../kiorex-platform/apps/api/src/telemedicine/*`: `TeleSession` (Kiorex-owned, `bookingId` unique) created from a CONFIRMED Kiorex booking; `VideoAdapter` (mock | Daily.co `DailyVideoAdapter`, `VIDEO_MODE`) creates rooms/tokens; patient `POST /telemedicine/sessions/:id/join`; and product-key HMAC endpoints for the clinic (`POST telemedicine/clinician/bookings/:bookingId/token` and `/end`) that **Clinic never calls** (grep: no usage). Matching uses `provider.raw.provider.telemedicine/videoConsultation/fees[].modality=VIDEO`. Join window is 15 min before to 2 h after.
- **Relationship / conflict.** Kiorex's model makes Kiorex the media-session owner (Daily) and Clinic only a consumer; the new requirement makes Clinic the owner (`TelehealthSession`, P2P). Both cannot own the session for the same booking. Recommended: Clinic is system of record (ADR-005); for `visitType=TELEHEALTH` bookings Kiorex stops creating Daily rooms and instead renders the `telehealth` block (join URL) returned by Clinic / pushed by `telehealth.session.created`; keep the Daily adapter dormant behind `VIDEO_MODE` (not removed). Needs a founder decision and a Kiorex-side task (open question Q1).
- Existing: `Telehealth` as an Encounter visit type string and a demo seed using it (`prisma/seed.ts` L988, L1049), env flag name `ENABLE_TELEHEALTH` in seed L1288 (unused elsewhere). No appointment-level telehealth anywhere in Clinic.

## 3. Implementation plan (commit order)

Naming decisions: module `src/telehealth/`, context `clinical` (like home-visits). Interfaces: `VideoProvider` (`P2PWebRtcProvider`, future `DailyProvider`), `SignalingTransport` (`HttpPollingSignaling`), `TurnCredentialsProvider` (`CloudflareTurnProvider`, `StunOnlyTurnProvider`). Visit type: add `ServiceLocation.VIDEO` (reuses existing type -> slot, hold, fee, commission narrowing) and expose it as `visitType: "TELEHEALTH"` in API/contract DTOs (derived field; documented). Appointment status stays the existing enum (no new values).

## 4. Encounter auto-creation design

- **Trigger points** (all converge on one function): (a) telehealth attendance (both ACTIVE 3 min) via the new `markAttended`; (b) any path that sets the appointment CHECKED_IN (manual by staff, `updateStatus`/`update`). Both already call `ensureDraftEncounterIfCheckedIn` in `appointments.service.ts`, so the simplest correct change is to **extend `ensureDraftEncounterOnCheckIn`** (`src/front-desk/ensure-draft-encounter-on-check-in.ts`) rather than add a parallel path:
  - read `serviceLocation`/session: `visitType: apt.serviceLocation === "VIDEO" ? "Telehealth" : "Outpatient"`;
  - `chiefComplaint` from `appointment.notes` (no complaint field exists on Appointment; Kiorex `notes` and staff notes both land there; trim to a limit);
  - keep patient, clinician, clinic, fee (`syncEncounterVisitFeeFromAppointmentSchedule`), `appointmentId`; date/time = the encounter's `createdAt` plus the appointment's `startsAt` shown via the linked appointment (Encounter has no start field).
- **Idempotency.** Today it only dedupes against DRAFT/AMENDED. Change the lookup to ANY status (`appointmentId` + tenant), and add a DB guard: partial unique index `CREATE UNIQUE INDEX ... ON "Encounter"("appointmentId") WHERE "appointmentId" IS NOT NULL AND "visitType"='Telehealth'` (or a general unique if founder agrees multiple encounters per appointment are never wanted; `EncountersService.create` currently allows several, so check existing data first). Wrap create in try/catch P2002 -> return existing id. Revert of check-in already deletes DRAFT encounters (`deleteDraftEncountersOnCheckInRevert`), keep that.
- **Who fills it.** Encounter editing is governed by nav tab `encounters` (`ENCOUNTERS_MUTATE_ROLES` = roles with that tab: PHYSICIAN, NURSE, RECEPTIONIST, CALL_CENTER, CLINIC_ASSISTANT, CLINIC_ADMIN, BRANCH_MANAGER, GROUP_ADMIN, GROUP_SUPERVISOR, HR_OFFICER-full set per `nav-tab-keys.ts`; FINANCE_OFFICER excluded). A PHYSICIAN only sees/edits encounters where `clinicianId` is self (`assertPhysicianEncounterAccess`). Finalize/amend (`@RequiresScope("encounter.sign")`): assigned clinician, or GROUP_SUPERVISOR/GROUP_ADMIN (`finalize`, `amend` checks); assistants can never sign (`scope-capabilities.ts`). So the auto-created draft needs no new permission model; the doctor reaches it from the call page ("Open encounter") and the assistant/supervisor from `/encounters`. Doctor reassignment after creation must also update the DRAFT encounter's `clinicianId`.
- **Edge cases:** patient profile incomplete blocks CHECKED_IN (`assertPatientProfileComplete`) -> for the system attendance path decide to skip the check rather than fail (Q7); encounter creation happens inside the same transaction as attendance; a no-show/cancel after attendance is not allowed (session ENDED/attended stays).

## 7. Cloudflare token permissions to request

- For the one-time setup script (creates the TURN key): a **Cloudflare API token** scoped to the single account with **Account > Realtime (formerly "Calls") > Edit**; Cloudflare's API doc for `POST /accounts/{account_id}/calls/turn_keys` accepts any one of "Realtime Admin", "Realtime", or "Calls Write". Request the narrowest: "Calls Write" / Realtime Write, account-scoped, with an expiry; no zone permissions. Discard it after the key exists (rotation only needs it again).
- The runtime credential is NOT a Cloudflare API token: it is the TURN key itself (`uid` = Turn Token ID, `secret` = bearer token returned once by the create call, 64 chars). Store `{"turnKeyId":"<uid>","apiToken":"<secret>"}` in `/kiorly-clinic/{env}/cloudflare-turn`; the API uses it only to call `POST https://rtc.live.cloudflare.com/v1/turn/keys/<uid>/credentials/generate-ice-servers` (body `{"ttl": seconds}`) and returns the resulting short-lived `iceServers` to the browser. No other Cloudflare permission is needed (no recording, no SFU/Realtime sessions, no DNS).
- Need from founder: Cloudflare account ID, confirmation of billing (TURN has a free tier then per-GB), and one TURN key per environment (staging, prod).
