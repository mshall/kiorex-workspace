## Identity (Kiorex Passport, ADR-012/013, KX-04)
- OIDC issuer `http://localhost:4400`; discovery at `/.well-known/openid-configuration`; JWKS at `/jwks`.
- Clients (dev): `kiorex-web` (public, PKCE, redirect `http://localhost:5180/auth/callback`),
  `kiorex-ops` (public, PKCE, redirect `http://localhost:5181/auth/callback`),
  `kiorex-mobile` (public, PKCE, redirect `kiorex://auth/callback` and `http://localhost:8081/auth/callback`),
  `kiorly-home` (public, PKCE, redirect `http://localhost:5194/signin/callback`, post-logout `http://localhost:5194/signin`; calls `GET /api/workspaces` on Passport),
  `kiorly-clinic` (confidential, secret `dev-kiorly-clinic-secret`, redirect `http://localhost:5174/auth/kiorex/callback`) — KCV-201 seam.
- Login: phone OTP. Dev OTP sender logs the code to the console AND, only when `NODE_ENV!=production`, accepts `000000` for numbers in the seeded test list.
- Access token = JWT (RS256), audience `kiorex-api`, claims: `sub`, `phone_number`, `phone_number_verified`, `name`, `locale`, `kx_roles` (e.g. `["patient"]`, `["ops_admin","super_admin"]`). **No clinical data in identity.**
- Back-channel logout: IdP POSTs `logout_token` to registered `backchannel_logout_uri` (`http://localhost:4000/api/v1/auth/backchannel-logout`, `http://localhost:3010/api/v1/auth/kiorex/backchannel-logout`). Event `session.revoked` / `subject.deleted`.

## Staff sign-in with Kiorex Passport (Clinic, Pharmacy, Lab; 23 Nov 2026)
Server side of "Sign in with Kiorex Passport" for the provider products. Passport proves identity only; **role, tenant and permissions always come from each product's own staff row** (ADR-013). Dev password / dev-login keep working.
- **Staff mobile app (public PKCE client `kiorly`, legacy `kiorly-team`)** sends the Passport **access token** (RS256, aud `kiorex-api`) as `Authorization: Bearer` to all three APIs. Accepted clients are checked via the `client_id` claim (`OIDC_ALLOWED_CLIENTS`, default `kiorly,kiorly-team`), so patient tokens (`kiorex-web`) are refused. Tokens refresh at Passport (`offline_access`), not at the product.
  - Clinic (branch `kiorex`): `KIOREX_OIDC_ISSUER` set (local stack) and `KIOREX_OIDC_ACCEPT_BEARER` not `false`; production needs `KIOREX_OIDC_ACCEPT_BEARER=true` or `AUTH_MODE=oidc`. `sub` -> `KiorexIdentityLink`; users with an enrolled second factor need `acr=urn:kiorex:acr:mfa` (SC-04).
  - Pharmacy / Lab: `AUTH_MODE=oidc` (Passport only) or, outside production, `AUTH_ACCEPT_PASSPORT=true` next to `AUTH_MODE=local|dev` ("dual", what `e2e/scripts/up.sh` runs). `OIDC_ISSUER` (Pharmacy) / `KIOREX_OIDC_ISSUER` (Lab). `sub` -> `StaffUser.subject`.
- **Linking.** Seeded for the demo staff (below). First login of anyone else: a **unique active staff row with the same verified phone** (`phone_number_verified=true`, E.164; Clinic = `Employee.phone`, Pharmacy/Lab = `StaffUser.phone`, Lab owners set it via `POST/PUT /staff {phone}`) is linked and audited (`KIOREX_IDENTITY_LINKED` / `auth.passport_linked`); no match, several matches or an unverified phone => 401/403 `PASSPORT_NOT_LINKED`. Never auto-created. Phone linking is OFF by default in production (`OIDC_PHONE_LINK=true` / `KIOREX_OIDC_PHONE_LINK=true` to opt in). The Clinic keeps its password re-auth link flow (`/auth/kiorex/link/start`) for the web.
- **Staff webs (Pharmacy :5192, Lab :5193)**: `GET /api/v1/auth/config` -> `{localLogin, passport}`; the SPA does authorize + PKCE (public clients `kiorly-pharmacy-web`, `kiorly-lab-web`, redirect `<origin>/auth/callback`), then `POST /api/v1/auth/oidc/exchange {code, codeVerifier, redirectUri, nonce}` (the IdP token endpoint is not CORS-enabled) returns the product session (+ `endSessionUrl`). **Sign-out** navigates to the stored RP-initiated logout URL (`/session/end?id_token_hint=...&post_logout_redirect_uri=<origin>/`, registered in `kiorex-account/config/idp.json`), which the dev IdP auto-confirms, so the Passport session ends too and "Sign in with Kiorex Passport" asks for the OTP again. Clinic web does the same through `POST /auth/kiorex/callback` (`endSessionUrl`, client `kiorly-clinic`, post-logout `http://localhost:5174/`).
- **Demo links** (phone, OTP `000000`): Clinic `+201000002001` owner.na@ (GROUP_ADMIN), `…2002` frontdesk1.na@ (RECEPTIONIST), `…2006` nadia.na@ (PHYSICIAN) + the Nurse personas (`…3001-3010`); Pharmacy `…2004` pharmacist@, `…2007` owner@, `…2008` cashier@ (`@demo.kiorly.local`); Lab (`demo-lab`) `…2005` tech@, `…2009` signatory@, `…2010` owner@. Seeds: `scripts/seed-all.sh` (Passport accounts 2006-2010 included).
- **Kiorly Home password handoff.** Each product API has `POST /auth/handoff/login` (Origin must be in `KIORLY_HOME_ORIGINS`) and `POST /auth/handoff/exchange`; the web login page redeems `?handoff=<code>` once (30 s, single use, hashed, product-bound) and strips it; `?reason=mfa` shows a notice. Spec: KX-08 section 13.
- **Kiorly Home hand-off (Clinic, Pharmacy, Lab webs).** `<product>/login?sso=passport[&from=kiorly-home][&edition=NURSE]` starts the Passport code flow automatically (silent when the Passport session exists); the header link "Switch workspace" goes to `<home>/signin?switch=1` (`VITE_KIORLY_HOME_URL`, dev default http://localhost:5194). Demo persona `+201000002031` (Home picker) is linked to `nurse.na@` (Clinic), `manager@demo.kiorly.local` (Pharmacy) and `manager@demo-lab.test` (Lab). Real-stack spec: `kiorex-account/apps/kiorly-home` `npm run test:e2e:real`; Kiorly app: `kiorly/e2e-web/real.config.ts`.
- **Staff management (phone).** Pharmacy (`POST /staff`, `PATCH /staff/:id`, web Settings > Staff and roles), Lab (`POST /staff`, `PUT /staff/:id`, web Settings > Staff) and Clinic (HR employee create/edit, `Employee.phone`) let an owner set the staff member's mobile number: strict E.164 (spaces/dashes tolerated, stored as `+<digits>`), unique inside the tenant (409 `PHONE_TAKEN`, 400 `INVALID_PHONE`), audited without the number (`linkKeySet` / `linkKeyChanged`), permission-guarded (`staff.manage`). Clinic stores `Employee.phone` as digits only (no `+`); the Passport link matches both spellings.
- **Back-channel logout (all three staff webs).** Passport POSTs a signed `logout_token` (typ `logout+jwt`, RS256, `aud` = the web client, `sid`/`sub`, `events`) to the client's `backchannel_logout_uri`: Clinic `/api/v1/auth/kiorex/backchannel-logout`, **Pharmacy and Lab `/api/v1/auth/oidc/backchannel-logout`** (form-encoded `logout_token`; 200 processed, 400 invalid or replayed; public route, the signed token is the credential). Receivers verify signature/issuer/audience/typ/events/`sid`|`sub`/no `nonce`, store the `jti` (replay protection shared by all instances), and end the matching `PassportSession` rows (Pharmacy/Lab; one row per web sign-in, its id is the session JWT `jti`, so the next request is 401 `SESSION_REVOKED`). `subject.deleted` ends every session of the subject and unlinks the staff row (kept). Raw Passport access tokens of the staff app are checked against the same revocations by `sid` (and by `sub` for tokens issued before a subject-wide logout). A session also ends when its staff member is deactivated. **Fallback when a logout is missed:** the web session lasts `OIDC_SESSION_MAX_AGE_SECONDS` (default 3600, clamped 60..28800; was a fixed 8 h) and the webs re-check `/auth/me` every minute. Register the URIs in `kiorex-account/config/idp.json` (done for local, staging and production; see Docs/NEEDS_HUMAN.md in each repo). E2E: `e2e/test/21-staff-web-session-revocation.e2e.ts`.

- Target: `POST http://localhost:4000/api/v1/webhooks/kiorly` (secret `kx_dev_webhook_secret`).
- Headers as Kiorly actually sends them (code wins over KX-09): `X-Kiorly-Event`, `X-Kiorly-Event-Id`, `X-Kiorly-Timestamp` (unix **seconds**), `X-Kiorly-Signature: sha256=<hex HMAC-SHA256 of "${timestamp}.${rawBody}">`. Use `verifyWebhook` from `@kiorex/contracts`.

## Vertical partners: Kiorex <-> Kiorly Pharmacy / Kiorly Lab (kiorex-contracts 1.4.1, first real-HTTP integration)

**Canonical ports** (everything else, e.g. 3020/3030, is obsolete and must not appear in any config): Pharmacy API 3100 / web 5192, Lab API 3200 / web 5193, Kiorly Clinic 3010, Kiorex 4000. Contracts: `kiorex-contracts/openapi/kiorly-pharmacy.v1.openapi.json`, `kiorly-lab.v1.openapi.json`, `kiorex-webhooks.v1.openapi.json` (`/webhooks/pharmacy`, `/webhooks/lab`).

**Conventions (decisions, resolve NH-PH-024 / NH-LB-025 / NEEDS_HUMAN #23 engineering side):**
- **Auth**: the Kiorly request HMAC (`signKiorlyRequest` / `verifyKiorlyRequest` from `@kiorex/contracts` on BOTH sides): `X-Kiorly-Client-Key`, `-Timestamp` (ms), `-Nonce`, `-Signature` over `ts\nnonce\nMETHOD\npath\nsha256(body)`; path = full request path without query. Events back use the webhook scheme (`signWebhook`/`verifyWebhook`: `X-Kiorly-Timestamp` seconds, `X-Kiorly-Event`, `X-Kiorly-Event-Id`, `X-Kiorly-Signature: sha256=hex`).
- **Partner addressing = the client key.** There is NO `X-Kiorex-Org-Id`. Each partner issues Kiorex an integration client whose key is bound to exactly one partner tenant (`IntegrationClient` in Pharmacy and Lab); the branch/lab is addressed by id in path/body (`pharmacyId` = branch id, `labId`). Org-scope feature flags for the partner products are keyed by the partner's own `Tenant.id`.
- **Per-partner secrets.** Kiorex stores one `PartnerRegistration` per partner (`baseUrl` = host only, `clientKey`, encrypted `clientSecret` + `webhookSecret`, `active`), editable by ops at `GET/POST/PUT /api/v1/admin/partners`; env vars `KIORLY_PHARMACY_*` / `KIORLY_LAB_*` are the fallback. Contract paths are appended by the client (`PARTNER_API_PATH`: pharmacy `/marketplace/v1`, lab `/api/v1/integration/v1`). Partner outbox events add `X-Kiorly-Client-Key`; Kiorex picks that partner's webhook secret (no key => env secret, never in production). Each partner stores its Kiorex base URL + sealed webhook secret on its `IntegrationClient` (`/api/v1/webhooks/pharmacy|lab`).
- **Flow, pharmacy**: Kiorex order intent (cart priced by `POST /catalogue/quote`) -> Kiorex Pay captures -> Kiorex outbox `POST /marketplace/v1/orders` (`orderId` = Kiorex order id = Idempotency-Key; unit prices must equal the pharmacy price book else 409 PRICE_CHANGED) -> Rx: `POST /prescriptions/validate` (Pharmacy verifies the token with Kiorex `GET /api/v1/rx/verify`; VALID only after a pharmacist validated, INVALID rejects the order) -> staff accept -> pharmacist sign-off -> `OrderReady` -> dispense -> `DispenseCompleted` (`partial` => Kiorex `PARTIAL_REVIEW`, no auto-release) / `OrderRejected` (full automatic refund). Partner 4xx (except 401 = our credentials) rejects + refunds; 5xx/timeouts retry with the same key.
- **Flow, lab**: tests/quote/slots from the Lab (price + capacity authority) -> booking -> Kiorex Pay -> `POST /integration/v1/orders` (`sourceRef` = booking id, `consentChannels: [KIOREX_VAULT]`) -> collection (`LabOrderStatusChanged` COLLECTED) -> QC-passing result -> sign -> release -> `LabResultReleased` -> vault record with the signed secure link only (never values) and funds released. Lab-side cancel before collection refunds in full.
- **Flags**: Kiorex `kiorex.pharmacy_orders` / `kiorex.lab_bookings` (launch-locked, gate evidence required) and partner `pharmacy.kiorex_orders` / `lab.kiorex_bookings` (products poll the Kiorex snapshot; product key `ff_<product>_dev` with `kiorly-pharmacy` / `kiorly-lab`). OFF at Kiorex => 403 FEATURE_DISABLED for new actions; OFF at a partner => Kiorex surfaces 403 FEATURE_DISABLED (`partner` field) and refunds paid orders.

## Nurse-collected lab samples: Kiorly Nurse -> Kiorex -> Kiorly Lab (kiorex-contracts 1.6.0, KNLAB01 / KLORD05)

Kiorly Nurse is an EDITION of Kiorly Clinic (ADR-031): no new repo, client or endpoint set. Flow (all HMAC, same schemes as everywhere):

## Connecting a standalone organisation (ADR-040)
Published in `kiorex-contracts` 1.9.0 (`openapi/kiorex-partner-intake.v1.openapi.json`, helpers in `src/intake.ts`, contract test `test/partner-intake.test.ts`): `POST /api/v1/partners/v1/connection-requests` and `GET /api/v1/partners/v1/connection-requests/:id` (header `x-connection-token`).
- **Authentication.** Kiorex ops create a one-time **enrolment code** per partner in the ops console (Partner onboarding > Enrolment codes, API `POST /admin/onboarding/enrolments`): `kxe_<id>.<secret>`, shown once, single use, expiring (default 7 days, max 14), revocable, audited, stored only as `sha256(code)`. The partner product asks for it in its "Request to go live" step (Clinic, Pharmacy and Lab wizards; the code is never stored). The FIRST request is signed with it (`X-Kiorex-Enrolment: kxe_<id>`); the response returns an **intake key** `kxi_...` once, which the product keeps (sealed) and signs every later request with (re-submit, credential rotation; no header). Signature `X-Kiorly-Signature: sha256=HMAC(hex(sha256(secret)), "<ts>.<rawBody>")`, `X-Kiorly-Timestamp` in unix seconds. The old schemes (shared Kiorly webhook secret for Clinic/Nurse, the submitted webhook secret for Pharmacy/Lab) are gone. A lost intake key is recovered by a new enrolment code for the same organisation (it issues a new key).
- **Replay protection.** 5 minute timestamp window plus a single-use `nonce` in the signed body (kept for an hour).
- **Limits.** Per IP 30 requests/minute (status poll 120/minute), per `kind+orgRef` 20/hour, and failed authentications per IP 12 per 10 minutes; over the limit => `429 RATE_LIMITED` with `Retry-After` (env `INTAKE_RATE_*`). Body cap 64 KiB (`413 PAYLOAD_TOO_LARGE`). Counters are in memory per API instance: put the WAF in front for a global cap.
- **Uniform errors.** Shape errors answer 400 before authentication (`INVALID_REQUEST`, strict: unknown fields refused). Every authentication failure (unknown, expired, used, revoked or wrong-kind/org code, bad signature, stale timestamp, replayed nonce) is the same `401 INTAKE_UNAUTHORIZED`; the status poll answers `404 PARTNER_CONNECTION_NOT_FOUND` for an unknown id or a wrong token. Audit lines carry ids and reason codes only (no PHI, no secrets).
Kiorex to Clinic: `GET|PUT /marketplace/v1/connection/:orgRef` over the existing signed marketplace API (ping with counts, ops decision). Ops console: Partner onboarding (`/partner-onboarding`). The product wizards are at Clinic `/kiorex/connect`, Pharmacy and Lab `/kiorex-connect`. e2e: `e2e/test/22-standalone-connect.e2e.ts`.

### Several live partners of one kind (routing per registration)
Every pharmacy cart, order and lab booking carries `registrationId` (API field `partnerId`); quote, order, Rx validation, cancel, slots and test search go to THAT registration only, and a webhook is bound to the registration whose secret verified it (an event for another registration's order is ignored and audited). Pharmacy branch / lab ids are matched to their registration from what each partner reports (cached 60 s; `partnerId` disambiguates an id two partners offer: `409 AMBIGUOUS_LOCATION`). Listings and searches without a location fan out to every live partner and tag items with `partnerId`; a partner whose org-scope flag `pharmacy.kiorex_orders` / `lab.kiorex_bookings` is OFF is hidden and refused with `FEATURE_DISABLED {scope: ORG}`. Per-org policy overrides (partial fulfilment) are keyed by the partner's organisation id. Rows older than the migration were backfilled to the single registration that served them. e2e: `e2e/test/23-multi-partner-routing.e2e.ts`; integration: `kiorex-platform/apps/api/test/partner-routing.int.spec.ts`.

**Nurse lab relay too (`lab_nurse`).** Registrations of kind `lab_nurse` carry `labRegistrationId` (the lab registration of the same lab tenant). A Nurse `LabOrderPlaced` is routed by `preferredLabId` to the lab registration that reports that lab and from there to its paired nurse client; `NurseLabRelay.registrationId` pins custody / status calls, and a lab event for another lab's order is ignored and audited (`nurse_lab.event_from_other_registration`). Unknown lab or unpaired nurse client: definitive `REJECTED_BY_LAB` (`LAB_NOT_FOUND`, `LAB_NURSE_NOT_REGISTERED`). Verified by `e2e/test/23` (real lab tenant B with its own `KIORLY_NURSE` client) and `test/partner-routing.int.spec.ts`.

**Search `earliest` sort.** The default sort orders the WHOLE catalogue by next in-clinic slot in SQL (`Provider.nextSlotAt`, refreshed lazily and by a 60 s warmer; providers without slots come last by rating then id), so unrated providers are reachable and pages are stable; `nextAvailable` filters on the same index. HOME searches (district-specific) keep a bounded in-memory path.
